Description:

As an exploration into sampling-based path planning algorithms as well as machine learning, I am working on this ongoing project to develop new ways of harnessing neural networks to increase sampling efficiency for sampling-based path planning methods. For this project, I implemented a Rapidly Exploring Random Tree (RRT) algorithm, as well as it's close optimal cousin RRT*, in a C++/Visual Studio environment in order to generate data for my neural network to learn on and evaluate with. I visualize the planning and environment using the SDL graphics library. The data I generate includes the positions and sizes of 4 randomly placed and sized circular obstacles, start position that is restricted to the left edge of the space, end position that is restricted to the right edge of the space, and the multi-variate distribution variables of the resultant solution path. You can see a sample scenario in Figure 1. I export this data 10,000 times in order to collect a sufficient dataset for training.

Figure 1: Sample scenario with RRT exploration

My neural network, created in Google Colaboratory with PyTorch and Python, is currently a multi-linear-layer model with a Tanh activation function. Specifically, my network has 2 hidden layers, each with a Tanh activation function, and a linear output layer and utilizes a built-in Adam optimizer. My network takes in the start and end positions in the given scenario as well as the positions and radii of the 4 defined obstacles, and predicts the multi-variate distribution variables that define the distribution most likely to contain the solution. By sampling on this predicted distribution, instead of uniformly, I hope to see a reduction in number of samples required to find the optimal path. See illustrations of the predicted distributions in Figure 2.

Figure 2: Sample scenario with predicted distribution

I have run a few different versions that have mixed results. My current network has been trained on data from an RRT (not an RRT*) for 1000 epochs with a learning rate of 0.02. Using mean absolute error (MAE), we begin with a loss of about 0.67 and end with a loss of about 0.16. In using this network, we achieve a reduced number of samples in 55% of test scenarios but this did not correlate to a reduced length of the calculated path. You can see some example sampling on the distributions below, Figures 3 - 5.

Figure 3-5: Example outputs. In each, the red oval is the sampling distribution, the light blue tree is the RRT sampling tree with uniform sampling, the green path is the solution from the uniformly sampled tree, the purple tree is the RRT sampling tree with sampling on the distribution, and the pink path is the solution from the tree sampled on the distribution.

I have achieved more optimal results by upgrading my planner to an RRT* algorithm instead of an RRT however many extreme cases are failing to succeed.

My next, and current, step is to adjust the structure of my network to train on generative data. In other words, designing a network that given previous steps, can generate the best next step. To accomplish this, I am implementing a conditional autoencoder structure and using samples from my RRT* solution paths in the same environments.
